## LLM Applications and RAG {#e1-retrieval-rag}

Build an LLM feature that retrieves relevant evidence, returns validated results, and shows where its answers succeed or fail.

**Before you start:** [Software Engineering for AI](/docs/softlanding/core-systems/software-engineering#r1), [LLM Fundamentals and Agent Workflows](/docs/softlanding/core-systems/llm-applications#llm-fundamentals), and basic API skills from [APIs, Containers & Deployment](/docs/softlanding/core-systems/apis-containers-deployment#r6).

### Learn

- Make model requests, manage messages and context, and handle timeouts, unavailable models, and invalid responses.
- Frame tasks clearly, generate structured outputs, and validate the response schema separately from factual correctness.
- Prepare documents with source metadata; use chunking, embeddings, similarity search, and a lexical-search baseline.
- Supply retrieved context, preserve source references, and handle questions with insufficient supporting evidence.
- Evaluate retrieval separately from answer correctness, grounding, and citation support.
- Compare one meaningful change and record quality, latency, and available usage or cost information.

### Practice

- Implement a small model-call feature with a documented response schema and failure handling.
- Build a knowledge base from public or approved documents and preserve source identifiers.
- Create evaluation questions with expected supporting passages, including questions the collection cannot answer.
- Compare a baseline with one change to chunking, retrieval depth, or search strategy; inspect retrieval and answer failures separately.
- Expose the feature through your application with source references and a clear insufficient-evidence response.

### Expected output

A working LLM/retrieval feature, validated response handling, evaluation questions, separate retrieval and answer results, and a short comparison explaining the chosen change and a meaningful failure.

## Agent Development and Tool Integration {#e2-agents-tools}

Build a bounded agent or tool-based workflow that completes a defined task with understandable execution and verifiable results.

**Before you start:** [Software Engineering for AI](/docs/softlanding/core-systems/software-engineering#r1), [LLM Fundamentals and Agent Workflows](/docs/softlanding/core-systems/llm-applications#llm-fundamentals), and basic API skills from [APIs, Containers & Deployment](/docs/softlanding/core-systems/apis-containers-deployment#r6). The introductory model-call material below provides the LLM preparation; completing the LLM Applications and RAG elective is not a prerequisite.

### Learn

- Make a basic model request and distinguish a fixed workflow from an agent that selects its next action.
- Define tools with clear descriptions, argument schemas, validation, results, and failure behavior.
- Execute tool requests through a controlled loop; manage task state, stopping limits, and recovery.
- Use scoped access and explicit approval points for actions that need them.
- Understand MCP clients, servers, and tools; inspect or implement a small integration when it fits your work.
- Evaluate task outcomes and execution traces, then compare with a simpler workflow using the same underlying tools.

## Model Adaptation and Experimentation {#e3-model-adaptation}

Determine whether adapting a pretrained model improves a defined task.

**Before you start:** [applied ML](/docs/softlanding/core-systems/applied-ml-deep-learning#r2) and [deep learning](/docs/softlanding/core-systems/applied-ml-deep-learning#r3); use [LLM Fundamentals and Agent Workflows](/docs/softlanding/core-systems/llm-applications#llm-fundamentals) for LLM-oriented projects.

### Learn

- Transfer learning and fine-tuning; select a model and dataset appropriate to the task and available compute.
- Prepare data, preserve an untouched test set, and establish the pretrained baseline.
- Track configurations, metrics, artifacts, and reproducible run information.
- Compare quality and resource use, and analyze regressions.

## Backend Architecture and Data Systems {#e4-backend-data}

Extend an AI service with reliable persistence and background work.

**Before you start:** [Software Engineering for AI](/docs/softlanding/core-systems/software-engineering#r1), [Systems, Networking & Data](/docs/softlanding/core-systems/systems-networking-data#r5), [APIs, Containers & Deployment](/docs/softlanding/core-systems/apis-containers-deployment#r6), and Engineering Fundamentals SQL.

### Learn

- Relational schema design, constraints, transactions, indexes, and query inspection.
- Separate request handling from a background task; track job state and handle retries.
- Use caching deliberately and explain invalidation or expiry.
- Define clear responsibilities between API, inference, database, and worker components.

## Delivery, Monitoring, and MLOps {#e5-delivery-mlops}

Make changes observable and releases recoverable.

**Before you start:** [Software Engineering for AI](/docs/softlanding/core-systems/software-engineering#r1), [Systems, Networking & Data](/docs/softlanding/core-systems/systems-networking-data#r5), [APIs, Containers & Deployment](/docs/softlanding/core-systems/apis-containers-deployment#r6); [ML evaluation](/docs/softlanding/core-systems/applied-ml-deep-learning#r2) or the LLM evaluation in [LLM Applications and RAG](#e1-retrieval-rag) provides the evaluation for your AI component.

### Learn

- Extend automated tests into a release workflow.
- Version application releases and model or prompt artifacts.
- Observe request latency, errors, and AI behavior using logs, metrics, and traces.
- Keep software regression tests and model/LLM evaluation visible.
- Deploy a new release, detect a failure, and restore a known working version.
