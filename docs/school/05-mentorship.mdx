# 🎓 Mentor's Guide

> **"For mentors and seniors using this open-source curriculum."**

This curriculum is designed to be self-driven by the student, but the **Mentor** is the critical accelerator. Your role is not to teach every concept, but to **unblock**, **verify**, and **challenge**.

## 🛡️ The Mentor's Role
You are not a lecturer; you are a Senior Engineer guiding a Junior.

1.  **Assign Modules**: Direct the mentee to specific phases (e.g., "Focus on *Math & ML Models* this week").
2.  **Unblock**: When they get stuck on an error for > 2 hours, provide a hint, not the solution.
3.  **Verify**: Don't trust; verify. Ask "Why?"
    *   *Why did you choose this loss function?*
    *   *Why is the validation loss diverging?*

## 🛠️ How to use this Curriculum
The curriculum defines **"What"** to learn. You define **"How well"** it is learned.

### Daily Evaluation
*   **Code Pushes**: Ensure they push to GitHub daily.
*   **Commit Messages**: Reject "fixed bug" messages. Demand "fix: handle null pointer in user auth".

### Code Review Standards
Review their submissions as if they were merging into your production branch.
*   **Clean Code**: Variable names must be descriptive.
*   **Modular**: No functions longer than 20 lines.
*   **Documented**: Public functions must have docstrings.

## 🏗️ The Capstone Project
Since this is an open-source path, **you (the Mentor) act as the Stakeholder**.

*   **Define the Problem**: Choose a problem relevant to your industry or the mentee's interest.
*   **Provide Data**: Point them to a Kaggle dataset, a public API, or a synthetic dataset.
*   **Set Constraints**:
    *   *"Must run on CPU under 100ms"*
    *   *"Must handle 10 concurrent requests"*
*   **Acceptance Criteria**: You decide when the project is "Production Ready".
