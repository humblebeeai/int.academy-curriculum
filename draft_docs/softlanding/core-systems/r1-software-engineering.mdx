# R1. Software Engineering for AI

Purpose: make your code understandable, testable, and easy for someone else to run. Prerequisite: Engineering Fundamentals Python, Git, terminal, and debugging skills.

## Learn

- Separate data preparation, model/inference logic, application code, and tests.
- Manage dependencies and configuration; keep credentials outside committed code.
- Write focused functions, meaningful names, useful errors, and logs that help diagnosis.
- Use unit and integration tests to check behavior, including invalid inputs.
- Work through issues, branches, pull requests, and review feedback.
- Use a coding assistant with a clear task, relevant repository context, and acceptance criteria; inspect its diff and verify the result.

## Resources

- [Clean Code: A Handbook of Agile Software Craftsmanship](https://www.oreilly.com/library/view/clean-code/9780136083238/) — Roadmap resource; optional reading if access is available. Focus on chapters 2, 3, 4, 7, and 9 for naming, functions, comments, error handling, and tests. Free resources below support the required practice.
- [uv: Working on projects](https://docs.astral.sh/uv/guides/projects/) — Added hands-on guide: create a project, add dependencies, and run it in a reproducible environment.
- [pytest: Get Started](https://docs.pytest.org/en/stable/getting-started.html) — Added practice: write tests and assertions, then use fixtures where shared setup is needed.
- [GitHub: Reviewing and testing AI-generated suggestions](https://docs.github.com/en/copilot/responsible-use/inline-suggestions) — Added reference: focus on intended uses, limitations, and verification. Apply the principles to your available coding assistant.
- [LeetCode: Programming Skills](https://leetcode.com/studyplan/programming-skills/) — Roadmap resource; optional exercises for specific implementation gaps. This does not replace the project task.

## Practice

- Refactor a notebook into a small Python project with a documented command to run it.
- Write tests for normal inputs, boundary cases, and a realistic failure.
- Implement one bounded change using an AI assistant. Review each changed file, test the result, and record an issue you corrected or a suggestion you rejected.
- Submit the change through a pull request and respond to review.

## Expected output

A runnable repository, meaningful tests, setup instructions, and a reviewed change. You can explain the code and fix a bug during discussion. If a coding assistant is unavailable, review a mentor-provided generated patch and complete the same verification task.

## Workload

Workload estimate pending pilot. Include practice, debugging, review, and revision in your study time.

## Submission evidence and completion checks

Keep the expected output, runnable instructions, test/evaluation results where applicable, and your explanation of a meaningful failure. Submit through review and record the resulting revision. Explain your approach and diagnose a relevant failure during review. Revise incomplete evidence after feedback; resource completion alone does not establish competence.
