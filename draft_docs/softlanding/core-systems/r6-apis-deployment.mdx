# R6. APIs, Containers, and Deployment

Purpose: make your AI component usable as a service. Prerequisite: [R1](/draft/softlanding/core-systems/r1-software-engineering) and [R5](/draft/softlanding/core-systems/r5-systems-data), plus a working inference function from [R2](/draft/softlanding/core-systems/r2-applied-ml), [R3](/draft/softlanding/core-systems/r3-deep-learning), or [R4](/draft/softlanding/core-systems/r4-llm-applications).

## Learn

- FastAPI routes, Pydantic request/response models, validation, error responses, and basic CORS.
- Load reusable model resources efficiently; use current FastAPI lifecycle guidance.
- Separate inference logic from HTTP handling; test both.
- Build a Docker image, configure runtime values, and run the service locally.
- Automate tests in a basic workflow, deploy to an assigned environment, and inspect health and logs.

## Resources

- [APIs Explained in 6 Minutes](https://www.youtube.com/watch?v=hltLrjabkiY) — Roadmap resource; introductory API concepts.
- [How to Use FastAPI: A Detailed Python Tutorial](https://www.youtube.com/watch?v=SORiTsvnU28) — Roadmap video; use it for the first app and endpoint examples. Check current documentation for implementation details.

- [GitHub Actions: Building and testing Python](https://docs.github.com/en/actions/tutorials/build-and-test-code/python) — Added practice; automate your tests on a push or pull request. Prior Engineering Fundamentals GitHub Actions practice can be reused and extended.
- [HTML, CSS, and JavaScript in 30 minutes](https://www.youtube.com/watch?v=_GTMOmRrqkU) — Roadmap resource; optional starter for a small browser client.
- [Learn DOM Manipulation in 18 Minutes](https://www.youtube.com/watch?v=y17RuWkWdn8) — Roadmap resource; optional support for displaying API results in that client.

## Practice

- Expose your model or LLM feature through a validated endpoint and provide example requests.
- Test a valid request, an invalid input, and an inference failure; add a basic health endpoint.
- Build and run a Docker image; verify configuration and logs from a fresh run.
- Add an automated test workflow and deploy the service. Use a small browser client or command-line client to demonstrate it.

## Expected output

A deployed service, a Dockerfile, passing tests, an automated test workflow, and setup/use instructions. Include model or LLM evaluation results separately from software test results. Deployment may use Academy infrastructure or an agreed hosted environment.

## Workload

Workload estimate pending pilot. Include practice, debugging, review, and revision in your study time.

## Submission evidence and completion checks

Keep the expected output, runnable instructions, test/evaluation results where applicable, and your explanation of a meaningful failure. Submit through review and record the resulting revision. Explain your approach and diagnose a relevant failure during review. Revise incomplete evidence after feedback; resource completion alone does not establish competence.
