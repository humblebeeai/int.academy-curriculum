# Learning Approach and Completion

Plan your time around implementation, debugging, review, and revision as well as reading and watching. The stage's calendar and hour allocation should be agreed for the cohort after the practice workload is sized.

## Learning sequence

- Start: verify prerequisites, create the repository, and begin R1's engineering habits.
- Model foundations: complete R2 and R3, keeping results and debugging notes.
- Applications and systems: complete R4 and R5, then build and deploy through R6.
- Depth: complete your two electives after their prerequisites; extend the integrated project where useful.
- Handover: demonstrate the application, explain the evidence, address feedback, and document the final result.

## A practice cycle for each module

- Study the assigned sections and run the examples.
- Change the example or build the module task yourself.
- Test expected behavior and inspect a meaningful failure.
- Explain your choices and request feedback.
- Revise the implementation and record what improved.

## Completion expectations

Complete all six required modules, two electives, and the integrated project. Resource completion supports progress; your implementations, explanations, debugging, and revisions demonstrate the learning outcomes.

- Correctness: the application and exercises behave as documented.
- Evaluation: results use suitable baselines, splits/test cases, and metrics.
- Engineering: another person can run the code, tests, and main workflow.
- Understanding: you can explain decisions and diagnose a relevant failure.
- Iteration: review feedback leads to a documented improvement.

## Using AI during the stage

Use AI tools to explore, implement, test, and review. You are responsible for the final behavior and for explaining submitted work. Record one representative AI-assisted change and how you verified it; keep generated claims about results aligned with what your tests and evaluations actually show.

## Resource access and scope

Use the assigned subset of each resource. Clean Code is optional reading when access is available; the required engineering work can use the linked free documentation. Keep compute and deployment small, using local models, Academy-provided endpoints, or agreed infrastructure where suitable.

## Workload

Workload estimate pending pilot. Include practice, debugging, review, and revision in your study time.
